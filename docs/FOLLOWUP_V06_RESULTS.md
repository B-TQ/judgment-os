# v0.6 结果：完整核心继续按需使用

2026-10-27。当前证据不足以默认叠加完整 Judgment Preserver。八道任务中，完整核心相对一句提醒为 **1胜、7平、0负**；唯一胜负由字数门槛决定，不是已经证实的推理提升。初始轮与修正隔离后的模型评审得到相同成对结论。**这不证明方法等效，也不证明通用有效或无效。**

## 设计与真实运行

另一个新对话一次性编写了八道自包含、虚构但可信的英文工作任务，声明未读核心、旧题、原始输出或研究历史。四道普通可选默认不完全适配，两道默认适配，两道精确控制。全部原样接受，没有筛掉基线做得好的题，没有根据结果调题。领域指南质量正常并明确允许合理适配；本研究不覆盖恶意或故意低质的指南。

生成前固定四组、种子20261028、每题每组一次、请求模型 `gpt-6.1-sol`、推理设置 `low`、只读原生工作区和现有订阅认证。32/32调用完成，没有失败、缺失、补位或重跑。每组获得同样硬性要求；质量锚点、评审关注点和精确期望值不进入生成提示词。核心自v0.2保持不变。冻结输入、输出和工作区文件均经核验；报告选择功能的后续修改单独记录，原版脚本字节保存在生成前检查点。

实际服务的模型修订版本未公开，不能把请求名称当成固定的实际版本。宿主背景指令和缓存上下文并非完全隔离。公开保留的完成事件只有32条最终消息，未见工具事件；这不是完整行为审计，文本评分也不证明未联网、未写文件或已实施建议行动。

## 两轮评审与隔离修正

每位评审仅应收到重新编号、随机排序的同题四份回答、真实任务要求、任务专属0–4锚点和公开确定性检查。初始两位评审为归档Project需求调用定位接口，接口附带了其他会话标题/短摘要。它们声明未用于评分，但无法证明没有影响，因此初始轮标记为**隔离不完整**，原始评分完整保留。

在已知初始结果后记录修正方案：另建两个明确为projectless的对话，无需需求归档或项目定位，禁止会话/项目清单、会话索引、全局状态和档案历史。只提供新的匿名材料。两位均披露实际文件读取范围，声明未查会话/项目/档案，未遇到其他对话摘要；只在指定材料和AGENTS精确祖先路径范围内检查。该控制依赖宿主和指令遵循，不能冒充操作系统隔离证明。

两轮分别分析，不挑选结果、不把四位评审并作更多任务样本。32份回答没有变化，没有新增处理组生成。每轮均有64条质量记录和96条成对记录；这些仍然只是八个案例的重复判断。所有评审均为模型，配置默认与实际修订未知，不是独立人工验证。两个修正评审之间门槛32/32一致、配对48/48一致，但30份通过回答中有4份质量整数不同；不能只引用配对一致率而宣称细微质量评估可靠。

## 使用决定与边界

保留原完整核心作按需试用和对照，不增加提示词复杂度来追求当轮优势。新增的实际成果是更透明的评测、隔离修正、分轮报告和更简明的安装/撤回/适用说明。软件可验证不等于方法已经成熟。

八道AI编写合成案例、每组一次、同供应商模型评审、未知实际修订、缺少独立人工效用和跨模型/宿主复现，都限制结论。不生成效果置信区间、p值或总体提升百分比。下一份有价值的证据应来自真实使用中的具体失败与独立人工判断，而不是不断改写同一批提示词直到出现胜出。

源码与公开说明不包含私密原回答、匿名映射、评分CSV或轨迹。实际本地记录按轮保留在私密实验备份：初始轮、隔离修正、原始32输出、冻结记录、配对收据、逐条证据、用量及修正理由均可复查。流程复现见[设计](STUDY_PROTOCOL_V06.md)与[同题评审](PAIRED_REVIEW.md)；使用入口见[怎样选用](USAGE_DECISION.md)。
